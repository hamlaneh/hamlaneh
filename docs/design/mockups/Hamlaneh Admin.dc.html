A different mode, the same family
Three things separate admin from chat, and nothing else does. Same tokens, same type, same focus and disabled treatments; no new colour and no new type step.

A deactivated row swaps the last item: Reactivate in brand.primary, not danger — it is constructive, and it restores sign-in without restoring the old sessions. Destructive items are last, separated by a rule, and coloured danger in the menu; they never appear as a filled red button in a row.

Behaviour
Destructive actions confirm and state the consequence in the confirmation, not in a tooltip.
Deactivating says sessions die; forcing a reset says the session survives. The difference is the whole point of the sentence.
You cannot remove the last admin — the action is blocked and explained, not warned about after the fact.
The temporary password is shown exactly once, behind a warning band, with copy and download offered before the only close button.
Org settings save immediately and say so in the page subtitle; there is no Save button to forget.
The audit log is read-only in the interface. Nothing here writes to it except the actions themselves.
Accessibility
Tables are real <table> markup with <th scope="col"> — the flex layout here is for the mockup only.
Status is a dot plus a word, and role is a tag whose fill differs as well as its colour.
Row focus is an inset 3 px ring so it is never clipped by the card's overflow.
Modals trap focus, close on Escape, and return focus to the control that opened them.
The credentials panel is the one dialog Escape does not close — it needs a deliberate acknowledgement.
Every nav row and table row is 44 px.
New icons this set needs
scroll-text · copy · refresh-cw · chevron-down · chevron-left · chevron-right · user-plus · user-minus. Everything else — users, link, settings, plus, download, ellipsis, check, alert, info, arrow-left — already ships with the auth and chat sets.
