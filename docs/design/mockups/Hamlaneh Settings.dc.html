01 · panel
A panel, not a page
Admin replaces the chat shell because it is a mode you enter. Settings float over it because they are a detour — the conversation stays visible, and Escape puts you back in it. No new tokens; the panel is surface at overlay elevation over the same scrim the chat drawer uses.

Behaviour
Escape closes the panel and returns focus to the sidebar gear; with unsaved edits it raises the leave-without-saving dialog first.
Typed fields commit with Save. Single choices — language, theme — commit on selection and show an inline Saved mark.
Changing your password does not end your other sessions, and the panel says so beside the form.
2FA setup never leaves a half-configured account: it is off until the code verifies and the codes are acknowledged.
A wrong code in step 2 does not restart setup — the secret stays valid and the cells clear.
Disabling 2FA re-asks for the password. If the org requires 2FA, the control is absent, not disabled.
Recovery codes are shown once. Regenerating invalidates the whole previous set and says so.
Accessibility
The panel is a focus-trapping dialog with an accessible name; the chat behind is inert, not merely dimmed.
The section nav is a tab list; arrow keys move between sections and the panel content is its tab panel.
Recovery codes are selectable text in a list, never an image, so a screen reader can read them and a password manager can grab them.
The manual 2FA key is always visible — someone who cannot use a camera never has to find a disclosure control.
Session rows pair the current-device badge with the word "Current" in its own column, so the state is not badge-only.
Step position is stated in words ("Step 1 of 3"), not only by the dots.
Every control in the panel is 44px.
Reuse and new icons
The OtpInput, PasswordField, NoticeBanner, PrimaryButton and radio group all come from the auth set unchanged. The toggle, select and confirm dialog come from admin. Nothing here is a new component except SessionRow, RecoveryCodeList and ThemePreview.
